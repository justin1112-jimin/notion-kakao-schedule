# 수익화 조사 (2026-09-10)

이 프로젝트(Notion→카카오 일정 알림)를 어떻게 수익화할 수 있을지 조사한 내용. 아직 결정된 사항은 없고, 실제 구현 전 참고용 자료.

## 조사 배경

v2(대시보드 고도화) 이후 Capacitor로 iOS/Android 앱 패키징이 예정돼 있어([[CLAUDE.md]] 참고), 유저가 늘어나기 전에 수익화 방향을 미리 점검해봄.

## 확인된 사실

- **카카오 "나에게 보내기"(`talk_message`) API는 발송 건수 제한이 없음.** 앱 전체 일일 쿼터(3만 건)만 걸리고, 핵심 기능(오늘 일정 카톡 발송)의 카카오 쪽 한계비용은 사실상 0원. 유저 수가 늘어도 카카오 메시지 자체는 병목이 아님. ([Kakao Developers - 이해하기](https://developers.kakao.com/docs/ko/kakaotalk-message/common), [쿼터](https://developers.kakao.com/docs/ko/getting-started/quota))
- **진짜 비용 병목은 Render/Upstash 무료 티어**: 무료 웹서비스 spin-down, Redis 무료 용량/커맨드 한도. 유저 수가 늘면 인프라 업그레이드 비용이 먼저 발생 — 수익화가 곧 "손실 방지"에 가까움.
- **Capacitor로 앱스토어에 올리면 애플/구글 인앱결제(IAP) 규정이 걸림.** 앱 안에서 구독을 팔면 애플은 26%(외부결제)~30%(인앱결제) 수수료를 가져감. 결제를 웹(브라우저)에서만 받고 앱은 로그인 후 보여주기만 하는 구조로 가면 이 수수료를 피할 수 있지만, 애플 심사 가이드라인상 "리더 앱" 예외에 해당 안 되면 리젝 위험이 있음 — **Capacitor 패키징 단계에서 다시 짚어야 할 이슈.**
- "친구/그룹챗에 보내기"(카카오 소셜 API)는 나에게 보내기와 별개로 심사·동의항목 추가가 필요함.

## 옵션별 평가

### 1. 프리미엄 구독 — 추천
- 무료: 캘린더 1개 연동(Notion 또는 Google), 발송 시각 1개, 기본 대시보드.
- 유료: 캘린더 다중 연동(Notion+Google 동시), 발송 시각 여러 개(아침/저녁), 발송 이력 무제한 보관/내보내기, 실패 시 우선 재시도, 대시보드 고급 통계.
- 장점: 이미 만들어둔 기능(다중 캘린더, 대시보드)을 상/하위로 나누기만 하면 됨. 인프라 비용을 유료 유저가 커버하는 구조가 자연스러움.
- 단점: 결제 연동(예: 토스페이먼츠) + 구독 상태 관리 로직 신규 개발 필요. 유저가 극소수인 지금 단계엔 과할 수 있음.

### 2. 광고 — 비추천
이 앱은 "보고 있는 화면"이 아니라 백그라운드 자동화라 광고 지면 자체가 거의 없음(설정/대시보드 정도). 유저당 방문 빈도도 낮아 의미 있는 광고 수익이 안 나옴. 앱 구조와 근본적으로 안 맞음.

### 3. 카카오 메시지 하단 스폰서 라인
발송 메시지 맨 아래 "협찬: OO" 한 줄 추가하는 뉴스레터식 스폰서십. 기술적으론 쉽지만 유저 수가 수만 단위는 돼야 광고주가 붙음. 지금 규모엔 시기상조.

### 4. 팀/그룹 요금제
"친구/그룹챗에 보내기"로 확장하면 회사/스터디그룹의 "공유 캘린더 → 단체 채팅방 아침 브리핑" 수요를 노릴 수 있음. 잠재력은 있으나 카카오 소셜 API 심사 + 스코프 추가가 필요해 개발 비용이 큼.

## 결론 / 다음 단계

지금 규모(1인 개발, 유저 극소수)에서는 결제를 바로 붙이기보다 **프리미엄으로 나눌 기능선을 먼저 설계**해두고, 실제 유저 증가로 인프라 비용이 발생할 때 구독을 켜는 순서를 권장. 광고는 배제, 팀 요금제는 카카오 소셜 API 심사가 걸려 있어 후순위 과제로 보류.
